Design prototype. It is not part of KeeneticOS and is not installed on a device. It builds a dnscrypt-proxy.toml that you can check with dnscrypt-proxy -check.

DNSCrypt, DNS-over-HTTPS and Oblivious DoH servers

The proxy sends queries to these servers, balanced by measured response time. At most 8 servers can be used, as on the DNS-over-TLS and DNS-over-HTTPS pages. Use servers from different operators for stable name resolution.

The port is part of the stamp and is chosen by the server operator. A server answers only on the ports it listens on. A server that does not listen on the new port is not reachable.

These three boxes only describe the server. For a personal profile, the address contains the profile identifier. Treat it as private.

Relay (Anonymized DNSCrypt and Oblivious DoH)

A relay hides your address from the server, and the server's answer is hidden from the relay. Use a relay and a server that are run by different operators. Oblivious DoH always needs a relay.

Choosing an interface needs the system integration. The proxy can mark its sockets with the Socket mark option below, and the system could map an interface to that mark.

Transport

DNSCrypt uses UDP by default. TCP helps when UDP is blocked or large packets are dropped, as can happen with relays. It adds delay.

Ports

The port of each server is part of its stamp and is chosen by the server operator. Servers on port 443 are less likely to be blocked by port-based rules. This does not hide that the traffic is DNSCrypt, and it is not protection against traffic analysis.
